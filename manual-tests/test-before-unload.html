Before Unload Tests

Closing a tab or window should run the page's beforeunload handler and, when the handler asks to stay, put up the confirmation dialog before anything is torn down. Answering Leave closes the tab; answering Stay must leave the tab exactly as it was — same page, same scroll position, same form contents.

State not armed

Two things have to be true before the dialog can appear: the handler must be registered, and the page must have had a real user interaction. WebKit suppresses the prompt for a page the user has never touched, so a page that is opened and immediately closed will close silently even with the handler installed — that is correct behaviour, not a bug in wig.

What to try

  1. Arm the handler (or type in the form), then close the tab with Ctrl+W. Answer Stay: the tab must survive with its text intact. Repeat and answer Leave: the tab closes.
  2. Cancel a close, then close again — the prompt must appear every time, never only the first.
  3. Close the same tab with the tab bar's × button and with a middle click. Both go through the same path and must prompt.
  4. Close the window with its × button. With several tabs open, arm this one only: the tabs that do not object close, and the window stays open holding this tab.
  5. Open a second window, arm this page, and use Close Other Tabs from the tab context menu on a different tab — each closing tab is asked in turn.
  6. Press the button below. A script-initiated close does not prompt, per spec: the tab should simply go away.
  7. Answer Stay, then reload with Ctrl+R. Navigation runs the same handler, so it should prompt as well.

Quitting with app.quit (Ctrl+Q) is a known exception: it does not go through this handshake, so it will not prompt.
